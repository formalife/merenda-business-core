# Chapter Specs

## Scopo

Questa directory contiene il contratto di contenuto della Fase 5.

Le specs sono raggruppate per parte del curriculum per ridurre frammentazione del repository. Ogni capitolo mantiene comunque una spec autonoma e verificabile.

File previsti:

- `part-01-fondamenti.md` — Capp. 1–4;
- `part-02-mercato.md` — Capp. 5–8;
- `part-03-posizionamento-offerta.md` — Capp. 9–13;
- `part-04-domanda-acquisizione.md` — Capp. 14–19;
- `part-05-copy-vendita.md` — Capp. 20–24;
- `part-06-lifecycle-brand.md` — Capp. 25–29;
- `part-07-economics-organizzazione.md` — Capp. 30–35;
- `part-08-crescita-capstone.md` — Capp. 36–39.

## Campi obbligatori di ogni spec

1. **Domanda** — problema a cui il capitolo risponde;
2. **Learning outcome** — cosa saprà decidere/fare il lettore;
3. **Prerequisiti** — capitoli/concetti già introdotti;
4. **Concetti obbligatori** — coverage minima;
5. **Causalità centrale** — relazione che organizza il capitolo;
6. **Decision framework / procedura** — come trasformare teoria in azione;
7. **Metriche/evidenza** — quando pertinenti;
8. **Errori da prevenire**;
9. **Esempi/casi**;
10. **Backend sources** — unità/crosswalk/sintesi;
11. **Collegamento** — cosa riceve dal capitolo precedente e cosa prepara;
12. **Definition first-use** — termini che devono essere definiti qui;
13. **Criteri di completezza** — gate per il draft.

## Regole

- una chapter spec non è prosa del libro;
- non aggiunge nuova dottrina;
- usa `PRIMARY_HOME_MAP.md` per evitare duplicazioni;
- usa `BEGINNER_GLOSSARY.md` per first-use;
- usa `PROVENANCE_MAP.md` quando un concetto è temporalmente/provenance-sensitive;
- usa casi sintetici solo se marcati come tali;
- non prescrive tattiche senza prerequisiti;
- non obbliga tutti i business a usare lo stesso canale, funnel o processo quando il corpus prevede condizioni diverse.

## Gate Phase 5

Ogni capitolo del curriculum deve avere una spec e nessun cluster primario deve restare senza casa.
